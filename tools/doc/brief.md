# 訳者への依頼（雛形）

作業フォルダへ写し、末尾の「担当」を訳者ごとに書き足して渡す。使い方は
[`README.md`](README.md)。

---

<製品名>（MSX 用の拡張BASIC）の公開文書を英訳する。読者はエンドユーザーと
アプリケーション作者。英語版は日本語版の訳で、食い違えば日本語版が正になる。訳した
結果は機械で日本語版と行ごとに突き合わせる。

このファイルと同じ作業フォルダに、次のものがある。

| | |
|---|---|
| `ja/<担当>.md` | 訳す原文（担当範囲だけを切り出したもの） |
| `glossary.md` | 訳語集。必ず従う |
| `headmap.tsv` | 見出しの対訳表（タブ区切り：文書名、日本語の見出し、英語の見出し）。見出しはこの英語を一字一句そのまま使う |
| `corpus/*.txt` | 兄弟の文書の日英対訳。`[タグ:行]`、`JA:`、`EN:` の3行で1組。原文と同じか、ほぼ同じ段落が兄弟にあれば、その英訳を使い、違うところだけ直す。訳語集に無い語もここを検索して兄弟に揃える |

## 守ること

1. **1行を1行に訳す。**出力の i 行目は原文の i 行目の訳。行を足さない、消さない、
   つながない、割らない。出力の行数は原文と同じ。空行は空行のまま。折り返した段落でも、
   語を前後の行へ動かさない
2. **行の形を保つ。**見出しの `#` の数、箇条の記号（`-` `1.`）と字下げ、引用の `>`、
   表の行（`|` の数を同じにする。`|---|` の行は変えない）、コードの囲み（```）
3. **見出しは `headmap.tsv` の英語をそのまま使う**
4. **リンクの行き先は一文字も変えない。**`(#日本語のアンカー)` も
   `(basic-reference.md#日本語のアンカー)` もそのまま残す（あとで機械で書き換える）。
   訳すのはリンクの文字（`[...]` の中）だけ。見出しを「…」で指しているリンクの文字は、
   対訳表の英語の見出しを "…" で書く
5. **インラインコード（`` `...` ``）は、ASCII だけのものを一字も変えない。**日本語を
   含むものだけ訳す（`` `<モード>` `` → `` `<mode>` ``）
6. **コードブロック。**```basic の中は、注釈の `'` より前をバイト単位で同じに保ち、
   `'` の後ろの日本語だけを訳す。言語の付いていない ``` の中（構文の説明）は、
   日本語の部分（`<モード>` のような置き換え部分と、日本語の語）だけを訳し、
   記号・英字・数字・空白の並びは変えない
7. **2桁以上の数字を落とさない。**範囲の `〜` は `-`（負の数を含む範囲は
   `-1200 to 1200`）。「16進」「10進」は hexadecimal / decimal、「16分音符」は
   sixteenth note のように語にしてよい。1桁の数は語で書いてよい
8. **強調を保つ。**`**...**` は対応する英語の句に付ける。`*...*` も同じ
9. 訳語は `glossary.md` に従う。無い語は `corpus` で兄弟の訳を探して揃える
10. 文体は簡潔な技術英語、現在形。説明を足さない。情報を落とさない
11. **原文を直さない。**原文が曖昧に読める、誤りに見える、前後と食い違う箇所は、
    原文に忠実に訳したうえで報告に挙げる

## してはいけないこと

- リポジトリのファイルを編集する。読むのはよい
- 担当の出力ファイル以外を書く
- Bash でヒアドキュメント（`<<`）を使う。止められる。ファイルは Write で書く

## 終わったら

出力ファイルを Write で書き、行数が原文と同じことを確かめてから、**日本語で**次を報告する。

- 原文と出力の行数
- 訳語集に無く、自分で決めた訳語（日本語 → 英語）。兄弟の訳に揃えたものはその旨
- 原文の疑わしい箇所（元の文書での行番号、原文の引用、何が疑わしいか）

## 担当

- 原文：`ja/<部分>.md`（元の文書 `doc/<名前>.md` の <最初>〜<最後> 行目。担当ファイルの 1 行目が元の <最初> 行目）
- 出力：`en/<部分>.md`
