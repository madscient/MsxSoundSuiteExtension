# ビルドとリリース

このリポジトリを保守する人向けの文書。ROM を使うだけなら
[README](../README.md) を参照。

## リポジトリ構成

| | |
|---|---|
| `docs/` | 公開ドキュメント。各ソースリポジトリからの複製と、この文書 |
| `tools/` | ビルド・パッケージ化・リリースのスクリプト |
| `vendor/` | 各拡張BASICのソースリポジトリ（サブモジュール、非公開） |
| `dist/` | 生成されたパッケージ（コミットしない） |

`vendor/` の4リポジトリはライセンスの都合で非公開のため、サブモジュールの
取得には各リポジトリへのアクセス権が要る。

## 前提

| | |
|---|---|
| Python | 3.x |
| zmac | [48k.ca/zmac.html](https://48k.ca/zmac.html)。環境変数 `ZMAC_EXE` で場所を指定 |
| GitHub CLI | [cli.github.com](https://cli.github.com/)。`gh auth login` 済みであること |

Linux では zmac をソースからビルドし（C 単体、依存なし）、`ZMAC_EXE` に
そのパスを渡す。

## 手順

```sh
git submodule update --init            # 4リポジトリを取得（--recursive は不要）
python tools/build.py                  # 全ROMをビルド
python tools/sync_docs.py              # docs/ を最新のソースから更新
python tools/package.py                # dist/ にパッケージと zip を生成
python tools/release.py v0.1.0         # ビルドからタグ付け・アップロードまで
```

`tools/release.py --dry-run` はビルドとパッケージ化だけを行い、タグ付けと
アップロードを行わない。

## スクリプト

| | |
|---|---|
| `tools/manifest.py` | ビルド手順・成果物・複製するドキュメントの定義。他の4本はここだけを読む |
| `tools/build.py` | 各サブモジュールのビルドスクリプトを順に呼ぶ |
| `tools/sync_docs.py` | `docs/` を更新する。`--check` で陳腐化を検査 |
| `tools/package.py` | `dist/` にパッケージと zip を生成する。生成前に下記の検査を行う |
| `tools/release.py` | 上記を通しで実行し、タグ付けとアップロードまで行う |
| `tools/release-notes.md` | リリースノートの定型文。`--notes-file` で差し替え可 |

成果物やドキュメントを増やすときは `manifest.py` だけを変更する。

## サブモジュールの配置

`vendor/Y8960BasicExtension` は自身も他の3リポジトリをサブモジュール参照して
いるが、ここでは初期化しない。Y8960 の `rom.py` は取り込む ROM を自身の
`vendor/` → `../<リポジトリ名>` の順に探すので、4つを `vendor/` に並べて置くと
後者がこちらのサブモジュールに解決される。結果、各リポジトリのチェックアウトは
1つで済み、カートリッジに入るのはいま自分がビルドしたイメージになる。

## カートリッジと単体版の同一性検査

`package.py` は、パッケージを作る前に、カートリッジイメージ `y8960bas.rom` に
埋め込まれた4本の拡張BASICが、いま `vendor/` でビルドしたものとバイト単位で
一致することを確かめる。一致しなければパッケージ化を拒否する。逃げ道は無い。

ROM に焼かれるバージョン文字列は日付までしか持たず、同じ日の別コミットから
作ったものは文字列が一致してしまうので、比較はバイト単位で行う。

取り込み元がどちらの木だったかも同時に見る。Y8960 の `rom.py` は自身の
`vendor/` を先に探すため、入れ子のサブモジュールが実体化しているとそちらが
使われ、カートリッジだけが別のコミットから来る。取り込み元が入れ子側だった
場合も拒否する。

`rom.py` 自身も両方の候補が在って中身が違えばビルドを止めるが、たまたま
同じなら止めない。こちらは同じでも拒否するので、ビルドが通ってパッケージ化で
止まることがある。そのときは入れ子を初期化解除して作り直す。

バンク配置は Y8960 の `tools/zbuild/targets.py` から読む。配置が動いても
こちらを直す必要はない。

## ドキュメントの複製

`docs/` 配下の各リファレンスは各ソースリポジトリの `doc/` からの複製で、
GitHub 上で非公開ソースなしに読めるようコミットする。`sync_docs.py` は複製時に
非公開ソースへ向いたリンクを外す。共存していた文書どうしのリンクは、配置を
保つことでそのまま生きる。

`package.py` は `docs/` がソースより古いとパッケージ化を拒否するので、
`sync_docs.py` の結果を先にコミットすること。`sync_docs.py --check` で書き換え
ずに確認できる。

### ドキュメントだけを更新する

ROM に変更がなく、ドキュメントだけを GitHub 上で新しくする場合はビルドを
挟まない。`sync_docs.py` はソースの `doc/` を読んで複製するだけなので、zmac も
ビルド済み ROM も要らない。

```sh
git submodule update --remote          # 1つだけなら vendor/<名前> を指定
python tools/sync_docs.py
git add -A && git commit && git push
```

`--remote` はサブモジュールを最新コミットへ進めるので、**ドキュメントだけを
取り込みたくてもソース側の変更が一緒にピンへ乗る**。以後のリリースはその
コミットからビルドされる。切り離したいときは、ドキュメント修正だけを含む
コミットをソースリポジトリ側で先に作り、そこへピンを合わせる。

リリース済みの zip に入っている `docs/` は公開時点で凍結されており、この手順
では変わらない。差し替えるなら ROM をビルドし直して再パッケージし、
`gh release upload <タグ> <zip> --clobber` を使う。GitHub 上の `docs/` が最新で
あれば足りることがほとんどで、軽微な修正でここまでする必要はない。

## リリースが指す状態

各リリースが4つのソースのどの状態を指すかはサブモジュールのコミットで決まる。
`release.py` は、このリポジトリに未コミットの変更があるとき、または
サブモジュールが記録されたコミットからずれているときは実行を拒否する。ROM に
焼かれるバージョン文字列は最終コミットの日付から作られるため、ずれた状態の
タグは誰も再現できないパッケージを指すことになる。

パッケージの `MANIFEST.txt` には、4リポジトリのコミットと全ファイルの SHA256
が入る。
