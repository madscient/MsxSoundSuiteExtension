# MSX Sound Suite 6リポジトリ共通のドキュメント規則

**この文書は、MSX Sound Suite を構成する6リポジトリに共通する、文書の書き方の
取り決め。** `doc/` か `README.md` か `CLAUDE.md` を書くか直すかする前に読む。
役割は仕様書、読者は6リポジトリで文書を書く AI と開発者、公開しない。

**正は MsxSoundSuiteExtension の `doc/msse-doc-rule.md` ひとつ。** 6本は自分の
`CLAUDE.md` か `README.md` から参照する。**写さない** ―― 写すと片方だけが
古くなる。同じ形で共有しているものが他に3つある。

| 文書 | 何の正か |
|---|---|
| [`msse-doc-rule.md`](msse-doc-rule.md)（この文書） | 文書の書き方 |
| [`naming.md`](naming.md) | 製品名の表記 |
| [`verification.md`](verification.md) | 検証の取り決め |
| [`../tools/doc/`](../tools/doc/README.md) | 公開文書の英語版の作り方と照合、訳語 |

## 文書の役割は3つ

書く前に、その文書がどれなのかを決める。役割が決まると読者が決まり、読者が
決まると書いてよいことが決まる。

- **成果物** — 外に出すもの。読者に開発者以外を含む。どこまで書けているかを
  進捗として持つ
- **仕様書** — 実装や文書が従う取り決め。守られているかどうかが問われる
- **情報リソース** — 判断の材料。従う対象ではなく、写しや調査の結果

## 「公開」かどうかは機械で決まる

**MsxSoundSuiteExtension の `tools/manifest.py` の `docs` に載っているかどうか。**
載っているものは `tools/sync_docs.py` が `docs/` へ複製し、GitHub で誰でも
読める。載っていないものは非公開のリポジトリの中にとどまる。

判断しない。**書く前に `manifest.py` を見る。**

公開する文書の読者は**エンドユーザーとアプリケーション作者**で、リポジトリを
見られない。

**MsxSoundSuiteExtension 自身は public リポジトリで、置いたものはすべて GitHub で
誰でも読める。** この規約のように役割が「公開しない」の文書も読める。そこでの
「公開しない」は読者がエンドユーザーではないという意味で、隠せるという意味では
ない。公開してよいことだけを書く。MsxSoundSuiteExtension の `README.md` と
`README.en.md` はエンドユーザーが読むので、製品名の表記は公開する文書と同じに
する。

## 各リポジトリは自分の文書の役割を記録する

`doc/` に何があって、それぞれ役割・読者・公開のどれなのかを持つ文書を、各
リポジトリが1本持つ。文書を足したか消したとき、役割か読者が変わったとき、
`manifest.py` の同期対象が変わったときに書き換える。

**他のリポジトリから文書を持ってきたときは、役割を必ず記録する。** フォークや
移植で来た文書は、元のリポジトリでの役割と、こちらでの役割が違うことがある。

## 書くときの約束

- **対象読者に不要な情報を書かない。** エンドユーザー向けの文書に、ソースの
  シンボル名、開発用文書への参照、段階番号、作業の依頼を書かない
- **公開する文書に履歴と経緯を書かない。** 現在の状態を静的に書く。履歴は
  非公開の `plan.md` 側に置く
- **同じ事実を2箇所に書かない。** 片方だけが古くなる。参照で済ませ、どちらが
  正かを書く
- **公開する文書からのリンクは、公開対象の中で閉じる。** 公開しない文書を
  指すリンクは、複製先で死ぬ。`sync_docs.py` が同期のあとに検査して止める
- **他リポジトリへの依頼は `prompt-*.md` に書いて渡す。** 役割は情報リソース、
  読者は相手のリポジトリのセッション、公開しない。**役目を終えたら削除する**

## 製品名の表記

[`naming.md`](naming.md) が正。一般名詞としての「拡張BASIC」と製品名の
使い分け、公開する文書で使う総称、変えてはならない識別子を定めている。

## 機械のことを成果物に書かない

**ローカルのパス、利用者の個人情報、それらから類推できるものを、リポジトリの
中の成果物とコミットメッセージに書かない。**

道具の置き場所は環境変数から取る。`OPENMSX_DIR` と `ZMAC_EXE` がそれで、
文書には**変数名だけを書く**。既定値を持たせない ―― 既定値は誰かの機械の
パスなので、書いた時点で成果物に入る。

## 行末

**文書は UTF-8、行末は LF。** 6本も MsxSoundSuiteExtension も `.gitattributes` が
`* -text` で Git 側の変換を切ってあるので、編集ツールが CRLF に書き換えると全行が差分に出る。
`sync_docs.py` は LF で書き出してバイト単位で比較するため、変換が入ると
`--check` が常に「古い」と言う。
