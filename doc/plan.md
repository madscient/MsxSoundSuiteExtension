## 統合する ROM の探し場所を呼ぶ側から渡す

Y8960 の `rom.py` は統合する4本を自身の `vendor/` と `../<repo>` の両方から
探し、両方在って中身が違えば止まっていた。Y8960 の作業機では兄弟の作業
リポジトリが常に並んでいるため、この検査が必ず発火して `vendor/` から組めな
かった。探し場所を呼ぶ側が環境変数で渡すことで候補が常に1つになり、この検査
そのものが要らなくなった。

依頼元は Y8960BasicExtension。依頼文書 `doc/prompt-msse-prebuilt-dir.md` は
4段が済んだので向こうで削除された（`e8f4471`）。

**外に出る値**：環境変数 `Y8960_PREBUILT_DIR`。4本のリポジトリが並んでいる
ディレクトリの絶対パス。読むのは Y8960 の `rom.py` と MSSE の `package.py`
だけなので、後から変えても波及先は2ファイル。

| | どちら | すること | 状態 |
|--:|---|---|---|
| 1 | MSSE | y8960 のステップに `Y8960_PREBUILT_DIR` を渡す | 済 `0319dcc` |
| 2 | Y8960 | `PREBUILT` に `rel` を足し、`rom.py` は渡された根＋`rel` だけを見る | 済 `d785baf` |
| 3 | MSSE | `package.py` の `check_cartridge_identity` を `rel` に切り替える | 済 |
| 4 | Y8960 | `paths` を消す | 済 `e8f4471` |

4段とも完了。`package.py` は `rel` を持たない `targets.py`（段2 より前の
gitlink）を名指しで拒否するので、ピンを戻した場合も黙っては通らない。

### 確度

- **確認済み** ―― `rom.py` が渡された値だけを見ること。`Y8960_PREBUILT_DIR`
  を外して `rom.py` を単体で走らせると、Y8960 自身の未初期化の `vendor/` を
  指して終了コード 1 で止まる。`build.py` 経由の通しビルドが通るのは、
  渡している値が効いているからだと言える
- **確認済み** ―― 通しのビルドとパッケージ化。5本すべてが組め、同一性検査は
  4バンクとも `vendor/` のビルド出力と一致した
- **確認済み** ―― 同一性検査が空振りでないこと。`mmbe_y8960.rom` の1バイトを
  反転させると `y8960bas` バンク #0 で拒否し、終了コード 1 になる。差分の位置
  （`0x0100`）まで出た。検査後に元へ戻し、sha256 の一致を確認済み
- **確認済み** ―― 二つの誤り経路。`rel` を持たない `targets.py` を渡した場合と、
  `rel` の指す像が無い場合に、それぞれの文面で `False` を返す
- **確認済み** ―― 段4（`e8f4471`）を取り込んでも出力が変わらないこと。組み直した
  `y8960bas.rom` が段3 の像と sha256 で一致し、パッケージ化も通る

## セッションの振り返り（2026-09-07、段1〜4）

4段の実施そのものは通った。取りこぼしが2つある。

### 「zmac が無い」と書いたが、あった

段1 の報告で「通しのビルドは未検証。この作業機に zmac が無い」と書いた。
確かめたのは `ZMAC_EXE` が未設定であることと `zmac` が PATH に無いことの
2つだけで、5本すべての `tools/zbuild/build.py` が既定値として
`D:\Programs\8bit\zmac\zmac.exe` を持っていることは見ていなかった。実際には
環境変数を明示的に外してもビルドは通る（`env -u ZMAC_EXE` で確認）。

不在の証明には探し場所の列挙が要るが、走らせるだけなら1回で済む。
**「資源が無いので検証できない」と書く前に、まず走らせる。** 失敗したら
その失敗の内容を書けばよく、そのほうが「無い」より正確でもある。

代償は人間の往復1回と、根拠の無い「未検証」がレビュー順序を狂わせたこと。
確度はその順序のために書いている。

### AI 同士の取り決めの是非を人間に諮った

段1 の報告で、依頼文書が提示した環境変数名 `Y8960_PREBUILT_DIR` の可否を
人間に確認した。判断材料は Y8960 の `rom.py` と MSSE の `package.py` にしか
なく、両方を読んでいるのはこちらだけである。人間には判断手段が無い。

原因は「外から見える値を決める直前に一声かける」を、渡された値にも当てはめた
こと。あの規則が見ているのは自分が新しく決める値である。渡された取り決めは
自分で評価して、採るか異議を書くかを決める。

### 繰り返す手順

同一性検査（`package.py` の `check_cartridge_identity`）に手を入れたら、
通ることの確認だけでは足りない。**`vendor/` のいずれかの `*_y8960.rom` を
1バイト反転させ、拒否して終了コード 1 になることまで見る。** 反転前に
控えを取り、確認後に戻して sha256 の一致を見る。通るだけの観測は、検査が
空振りでも同じに見える。
